# «Перечень тендеров» для Telegram-бота

API для бота, который работает в чате команды (сейчас — @SU10TenderNotes_BOT):
- напоминания по тендерам «Направлено» и «Ожидание ПД»;
- карточка тендера по запросу;
- запись звонка или события в хронологию тендера.

Правила сроков, тексты и склонения живут в TenderHUB. API отдаёт **готовые сообщения**
(HTML и кнопки), бот только отправляет их в чат и передаёт ответы пользователей обратно.

Base URL: `https://tender.su10.ru`. Все пути ниже начинаются с `/api/v1`. Ответы
приходят в конверте `{"data": …}`. Ошибки — RFC 7807 с полем `code`.

## Ключ

Ключ выпускает администратор: «Настройки → Доступ к API → Выпустить ключ».
- Название — например, «SU10TenderNotes_BOT».
- Права: **«Чтение перечня тендеров»** (`registry:read`) и **«Хронология и напоминания перечня»**
  (`registry:write`).
- Список тендеров **не задавать**: у перечня нет связи с тендерами, поэтому ограниченный ключ получит 403.
- Срок действия — по желанию.

Передавать ключ в заголовке `X-API-Key: thk_…`, **не** в `Authorization: Bearer`.
Эти маршруты открыты только по ключу: пользователь с обычной сессией портала получит
`403 API_KEY_REQUIRED`.

## Готовое сообщение `message`

Поле `message` есть в каждом ответе. Это параметры метода Bot API `sendMessage` без `chat_id`:

```json
{
  "text": "📞 <b>Надо позвонить</b>\nПо тендеру «<b>ЖК Ода</b>» (№330, ООО Ромашка) …",
  "parse_mode": "HTML",
  "reply_markup": {"inline_keyboard": [
    [{"text": "📞 Звонок", "callback_data": "tc:0f8fad5b-…"}, {"text": "📝 Событие", "callback_data": "te:0f8fad5b-…"}],
    [{"text": "Открыть перечень", "url": "https://tender.su10.ru/tenders"}]
  ]}
}
```

Отправка: `sendMessage({chat_id, ...message})`. Если кнопок нет, `reply_markup` отсутствует.
Текст уже экранирован и умещается в лимит Telegram (4096 символов).

**Кнопки** (`callback_data` ≤ 64 байт, `<id>` — uuid строки перечня):

| Префикс | Что сделать боту |
|---|---|
| `ti:<id>` | показать карточку тендера — `GET /tender-registry/{id}/card` |
| `tc:<id>` | записать **звонок** (`type: call_follow_up`): попросить текст, затем `POST …/chronology` |
| `te:<id>` | записать **событие** (`type: default`): так же |

Если у бота уже есть свои кнопки с префиксами `ti:`, `tc:` или `te:`, сообщите в TenderHUB:
префиксы поменяем.

## Эндпоинты

### `GET /tender-registry/search?q=<запрос>` — область `registry:read`

Поиск по номеру, названию и заказчику (без учёта регистра, «ё» = «е»). `q` — от 1 до 100 символов.
Сначала идёт точное совпадение номера.

```json
{"data": {"query": "ода", "total": 2,
  "items": [{"id": "…", "number": "330", "title": "ЖК Ода", "client": "ООО Ромашка",
             "status": "Направлено", "dashboard_status": "sent"}],
  "message": {…}}}
```

`message` — всегда одно сообщение для отправки:
- ничего не нашлось — «нет совпадений»;
- **одно** совпадение — сразу карточка тендера;
- несколько — список кнопками `ti:<id>`, не больше 10.

`dashboard_status` — вкладка страницы: `calc` | `sent` | `waiting_pd` | `archive`.

### `GET /tender-registry/{id}/card` — область `registry:read`

```json
{"data": {"tender": {"id": "…", "number": "330", "title": "ЖК Ода", …}, "message": {…}}}
```

В карточке:
- заказчик, статус, объём, площадь, стоимость КП;
- даты: подача КП, приглашение, выход на площадку, ввод;
- адрес, тендерный пакет;
- для «Направлено» — сколько дней без звонка;
- последние 3 записи хронологии.

Под карточкой — кнопки `tc:` и `te:`. Если тендера нет — `404 REGISTRY_NOT_FOUND`.

### `POST /tender-registry/reminders/claim` — область `registry:write`

Тело: `{"chat_id": -1001234567890}` — чат, куда бот отправит напоминания.

```json
{"data": {
  "window": {"from": "09:00", "until": "21:00", "timezone": "Europe/Moscow", "open": true},
  "items": [{"kind": "call", "due_on": "2026-09-30",
             "tender": {"id": "…", "title": "ЖК Ода", …}, "message": {…}}]}}
```

- Возвращаются только напоминания, которые **этому чату ещё не выдавались**. Выданное сразу
  запоминается, поэтому повторный вызов в тот же день вернёт `items: []`. Вызывать можно
  хоть каждые 10 минут.
- Вне окна 09:00–21:00 по Москве `open: false`, `items: []`.
- Виды напоминаний:
  - `call` — тендер «Направлено», с подачи КП или последнего звонка прошло **больше 7 дней**.
    Приходит каждый день, пока звонок не отмечен.
  - `waiting_pd` — тендер «Ожидание ПД», прошёл очередной месяц с последней записи хронологии
    (или с добавления в перечень, если записей с датой нет). Если бот был выключен, догоняет до 7 дней.
- Каждое напоминание выдаётся **один раз**. Если отправить не удалось (сеть, `429 Too Many
  Requests`), бот повторяет отправку **сам**: API его второй раз не выдаст.
- `items` всегда массив, в порядке строк перечня.

### `POST /tender-registry/{id}/chronology` — область `registry:write`

Тело:

```json
{"text": "Позвонили, ждут решения до пятницы", "type": "call_follow_up", "date": "2026-09-30T09:15:42Z"}
```

| Поле | Правило |
|---|---|
| `text` | от 1 до 2000 символов; пробелы по краям обрезаются |
| `type` | `call_follow_up` — звонок (сбрасывает 7-дневный отсчёт «Направлено»); `default` — событие |
| `date` | RFC3339. Передавайте **время сообщения пользователя** (`message.date` из Telegram, переведённое в UTC). Не старше 30 дней и не в будущем |

Ответ:
- **201** — запись добавлена;
- **200** — такая запись (`date` + `text` + `type`) уже есть, второй раз не добавлена.

Поэтому повтор запроса после сетевой ошибки безопасен.

```json
{"data": {"created": true, "title": "ЖК Ода",
  "entry": {"date": "2026-09-30T09:15:42.000Z", "text": "…", "type": "call_follow_up"},
  "message": {"text": "✅ Записал в хронологию «ЖК Ода»: 📞 Звонок — …", "parse_mode": "HTML"}}}
```

`message` — подтверждение, его удобно отправить ответом на сообщение пользователя. Автора у
записи в хронологии нет; если нужно, допишите имя в `text` («… — Иван»).

## Как устроить бота

1. **Напоминания.** По расписанию, раз в 10–30 минут:
   - вызвать `claim` с `chat_id` чата команды;
   - каждый `items[].message` отправить в чат;
   - между сообщениями держать паузу **не меньше 3 секунд**: у группы лимит около 20 сообщений в минуту;
   - при `429` подождать `retry_after` и повторить это же сообщение.
2. **Поиск.** Команда, например `/t 330` или `/t ода` → `search?q=…` → отправить `message`.
   В группе с включённым режимом приватности (по умолчанию) бот видит только команды и
   ответы на свои сообщения. Поэтому поиск — только через команду.
3. **Кнопка `ti:`** → `card` → отправить `message`, закрыть «часики» (`answerCallbackQuery`).
4. **Кнопки `tc:` и `te:`:**
   1. Отправить запрос текста с `reply_markup: {"force_reply": true, "selective": true}`,
      упомянув нажавшего — тогда поле ответа откроется только у него. Например:
      `📞 Звонок по тендеру «ЖК Ода» — <a href="tg://user?id=…">Иван</a>, ответьте на это сообщение: чем закончился звонок.`
   2. Запомнить у себя `(chat_id, message_id запроса) → (id тендера, type)` примерно на сутки.
   3. На ответ пользователя (`reply_to_message.message_id` = id запроса) вызвать
      `POST …/{id}/chronology` с `text` ответа, `type` и `date` = `message.date`.
      Отправить полученное `message` ответом на его сообщение.
   4. Название тендера для текста запроса есть в `tender.title` карточки или напоминания.

## Ошибки

| HTTP | `code` | Что значит |
|---|---|---|
| 401 | — | ключ не передан, неверен, отозван или истёк |
| 403 | `API_KEY_REQUIRED` | запрос пришёл не по ключу (сессия портала) |
| 403 | `API_KEY_SCOPE_DENIED` | у ключа нет нужной области (`requiredScope` в ответе) |
| 403 | `API_KEY_TENDER_DENIED` | ключ ограничен списком тендеров — для перечня так нельзя |
| 400 | `REGISTRY_INVALID_REQUEST` | неверный запрос; причина — в `detail` |
| 404 | `REGISTRY_NOT_FOUND` | тендера нет в перечне (удалили) |
| 429 | — | превышен лимит вызовов ключа в минуту |

Все вызовы видны в журнале: «Настройки → Доступ к API».

## Проверка связи

```bash
KEY=thk_…   # не оставляйте ключ в истории оболочки
curl -s -H "X-API-Key: $KEY" "https://tender.su10.ru/api/v1/tender-registry/search?q=330"
curl -s -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
  -d '{"chat_id": -1001234567890}' https://tender.su10.ru/api/v1/tender-registry/reminders/claim
```

Первый `claim` для **тестового** чата помечает напоминания выданными только этому чату.
Чат команды получит их при своём вызове.
