# Архив смет — поиск аналогов и сборка

Поиск позиций заказчика по всем прошлым тендерам, подбор аналогов и сборка новых позиций
целевого тендера на их основе. Общие шаги (выпуск ключа, заголовок `X-API-Key`, ошибки
доступа) — в [README.md](README.md); список маршрутов — в [ENDPOINTS.md](ENDPOINTS.md).

## Права ключа

| Область | Что открывает |
|---|---|
| `archive:read` | поиск, батч-подбор, чтение исторической позиции |
| `archive:write` | `compose` — запись в целевой тендер |
| `tenders:read` | выбрать целевой тендер и узнать id его позиций |

Ключ с ограничением по тендерам пишет через `compose` только в разрешённые тендеры и
читает историческую позицию только из них. Каждый маршрут архива администратор может
выключить отдельно — тогда он отвечает `503 ENDPOINT_DISABLED`.

## Эндпоинты

### `GET /api/v1/archive/positions/search` — похожие позиции

| Параметр | |
|---|---|
| `q` | название работы, обязателен |
| `unit_code`, `volume`, `item_no` | единица, объём и шифр искомой позиции — участвуют в оценке |
| `limit` | сколько вернуть. **Передавайте явно:** без него вернётся до потолка выдачи (200) |
| `min_score` | отсечка по оценке, по умолчанию 0.35 |
| `exclude_tender_id` | не искать в этом тендере (обычно целевой) |
| `period_months` | только тендеры за последние N месяцев |
| `only_latest_version` | одна версия на номер тендера, по умолчанию `true` |
| `with_boq_only` | только расценённые позиции, по умолчанию `true` |
| `approved_only` | только согласованные тендеры, по умолчанию `false` |
| `candidate_limit` | сколько кандидатов отобрать до оценки; без него — потолок (4000) |

Каждое попадание несёт `score`, `score_breakdown`, контекст тендера (номер, версия,
заказчик, дата, признак согласования) и удельные стоимости позиции — по ним видно, какая
история релевантна.

### `POST /api/v1/archive/positions/suggest` — батч-подбор

```json
{
  "queries": [
    {"ref": "1", "work_name": "Кладка стен", "unit_code": "м3", "volume": 420},
    {"ref": "2", "work_name": "Монтаж дверей"}
  ],
  "limit_per_query": 5
}
```

До 100 запросов в теле (потолок настраивается; больше — 400). Кроме `queries` принимает
`limit_per_query`, `min_score`, `exclude_tender_id`, `period_months`,
`only_latest_version`, `with_boq_only`, `approved_only` — смысл тот же, что у `search`.
`limit_per_query` тоже передавайте явно: без него на каждый запрос вернётся до 200 позиций.

### `GET /api/v1/archive/positions/{id}` — состав позиции

Позиция, тендер-источник (включая его курсы — как справка) и все строки BOQ. Нет такой
позиции — `404 ARCHIVE_SOURCE_POSITION_NOT_FOUND`.

### `POST /api/v1/archive/compose` — сборка

Собирает позиции целевого тендера из исторических. До 200 групп в запросе, до 50
источников в группе.

> **Без `"dry_run": true` запрос пишет в тендер.** Умолчание поля — `false`.

## Как считается похожесть

Двухступенчато: грубый отбор кандидатов по значащим словам названия, затем взвешенная
оценка — название 50, шифр `item_no` 30, единица 10, объём 10. Нормировка идёт **только
по применимым** компонентам: если в запросе нет `item_no`, это не топит кандидата.
Близость названия считается по совпадению значащих слов: «Бетон М150» против «Бетон М200»
— конфликт марки со штрафом, а не «почти совпало».

## Сценарий: найти аналог → проба → запись

```bash
BASE=https://tender.su10.ru
H="X-API-Key: $TENDERHUB_API_KEY"
```

### 1. Найти похожие позиции

```bash
curl -sG --compressed "$BASE/api/v1/archive/positions/search" -H "$H" \
  --data-urlencode 'q=Устройство цементно-песчаной стяжки' \
  --data-urlencode 'unit_code=м2' \
  --data-urlencode 'volume=1200' \
  --data-urlencode "exclude_tender_id=$TARGET_TENDER" \
  --data-urlencode 'limit=10'
```

### 2. Посмотреть состав понравившейся позиции

```bash
curl -s --compressed "$BASE/api/v1/archive/positions/$SRC_POSITION" -H "$H"
```

### 3. Прогнать сборку вхолостую

```bash
curl -s -X POST "$BASE/api/v1/archive/compose?verbose=1" \
  -H "$H" -H 'Content-Type: application/json' -d @- <<JSON
{
  "target_tender_id": "$TARGET_TENDER",
  "dry_run": true,
  "groups": [{
    "temp_id": "g1",
    "target": {
      "new_position": {
        "work_name": "Устройство стяжки",
        "unit_code": "м2",
        "volume": 1200,
        "manual_volume": 1200
      }
    },
    "sources": [{
      "source_position_id": "$SRC_POSITION",
      "scale": { "mode": "volume_ratio" }
    }]
  }]
}
JSON
```

`dry_run` выполняет ту же самую транзакцию и откатывает её. Значит:

- срабатывают все проверки базы и валидации — ответ честный, а не «прикидка»;
- суммы (`total_amount`, `total_material`, `cached_grand_total`) настоящие, посчитанные
  по настройкам и курсам **целевого** тендера;
- в базе не остаётся ничего, в журнале изменений записей нет;
- id новых строк не отдаются — вместо них `index` / `parent_index`.

`?verbose=1` добавляет в ответ построчный список `items`. Смотрите `warnings`:
`LINKED_QUANTITY_REDERIVED` означает, что у исторической строки количество привязанного
материала расходилось с формулой, и в цель уехало пересчитанное значение.

### 4. Записать

Тот же запрос с `"dry_run": false`. Проверка после записи:

```bash
curl -s --compressed "$BASE/api/v1/tenders/$TARGET_TENDER/overview" -H "$H"
```

`cached_grand_total` в шапке должен совпасть с `cached_grand_total` из ответа сборки.

## Тело `compose`

| Поле | |
|---|---|
| `target_tender_id` | целевой тендер |
| `dry_run` | `true` — проба с откатом; по умолчанию `false` — запись |
| `options.on_missing_source` | `fail` (по умолчанию) или `skip` — пропустить исчезнувший источник |
| `options.copy_quote_dates`, `options.copy_detail_cost_category`, `options.quantity_decimals` | переносить ли даты КП и категорию затрат; округление количества (0–9 знаков) |
| `groups[].temp_id` | ваша метка группы, уникальна в запросе |
| `groups[].target` | ровно одно из двух: `position_id` существующей позиции или `new_position` |
| `groups[].target.new_position` | `work_name` обязателен; `unit_code`, `volume`, `manual_volume`, `item_no`, `position_number`, `section_number`, `position_name`, `client_note`, `manual_note`, `hierarchy_level`, `is_additional`, `parent_position_id` |
| `groups[].sources[].source_position_id` | историческая позиция |
| `groups[].sources[].source_item_ids` | взять только эти строки; по умолчанию все |
| `groups[].sources[].scale` | `mode`: `none`, `factor` (с полем `factor`) или `volume_ratio` (объём цели / объём источника; можно задать `source_volume` и `target_volume` явно) |

## Что нужно знать перед записью

- **Сначала тендер, потом позиции.** `GET /api/v1/tenders/brief` даёт id тендера,
  `GET /api/v1/tenders/{id}/positions` — id существующих позиций. Если целевых позиций
  ещё нет, создавайте их прямо в `compose` через `new_position`.
- **Одна группа = одна целевая позиция.** Связь материал → работа не может пересекать
  позицию. Слить несколько исторических позиций в одну целевую можно — перечислите их в
  `sources`.
- **Валюта не конвертируется.** `unit_rate` и `currency_type` переносятся как есть, курс
  применяется целевой. Нет у целевого тендера нужного курса — `400 MISSING_FX_RATE` и
  полный откат: иначе строка ушла бы в базу с нулевой суммой.
- **Производные значения не копируются.** `total_amount` и коммерческие стоимости считает
  сервер внутри той же транзакции.
- **Масштабирование.** Работы и самостоятельные материалы умножаются на коэффициент.
  Материал, привязанный к работе, пересчитывается от масштабированной работы
  (количество работы × коэффициент перевода × коэффициент расхода).
- **Идемпотентности нет.** Повторный POST соберёт всё второй раз. Защита — `dry_run` и
  контроль на вашей стороне.
- **Частичной сборки не бывает.** Любая ошибка 4xx откатывает транзакцию целиком.

## Коды ошибок

| Код | Статус | Когда |
|---|---|---|
| `ARCHIVE_TARGET_SPEC_INVALID` | 400 | цель группы задана неверно (ни одного или оба ключа) |
| `ARCHIVE_NOTHING_TO_COMPOSE` | 400 | после фильтрации копировать нечего |
| `ARCHIVE_SCALE_UNDEFINED` | 400 | `volume_ratio` без объёма источника или цели |
| `ARCHIVE_SCALE_INVALID` | 400 | недопустимый `factor` или неизвестный режим |
| `ARCHIVE_QUANTITY_UNDERFLOW` | 400 | после масштабирования количество стало нулевым |
| `INVALID_BOQ_PARENT` | 400 | `source_item_ids` исключил родительскую работу |
| `MISSING_FX_RATE` | 400 | у целевого тендера нет курса скопированной валюты |
| `ARCHIVE_TARGET_POSITION_NOT_FOUND` | 404 | целевой позиции нет |
| `ARCHIVE_SOURCE_POSITION_NOT_FOUND` | 404 | позиции-источника нет |
| `ARCHIVE_SOURCE_ITEM_NOT_FOUND` | 404 | в `source_item_ids` строка чужой позиции |
| — | 404 | целевого тендера нет (ответ без поля `code`) |
| `ARCHIVE_DUPLICATE_TARGET` | 409 | один `temp_id` или одна целевая позиция дважды |
| `ARCHIVE_TARGET_TENDER_MISMATCH` | 409 | целевая позиция принадлежит другому тендеру |
| `ARCHIVE_CONCURRENT_MODIFICATION` | 409 | тендер изменили параллельно, сборка отменена — повторить |
| `API_KEY_SCOPE_DENIED` | 403 | ключу не выдана нужная область |
| `API_KEY_TENDER_DENIED` | 403 | тендер вне списка, разрешённого ключу |
| `ENDPOINT_DISABLED` | 503 | маршрут выключен администратором |
| — | 429 | превышен лимит запросов в минуту для ключа |
