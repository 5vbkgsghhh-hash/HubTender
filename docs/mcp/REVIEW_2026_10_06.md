# Self-review: direct VOR pricing

Date: 2026-10-06, Europe/Moscow. Reviewed PR #1 at `0b3b02d` against `2b2e867`.
No production writes, migration or deployment were performed.

## Confirmed defects and corrections

### P1 — concurrent receipt FK lock upgrades deadlock

Two distinct commands inserted receipts referring to the same tender, each
holding FK KEY SHARE. Both then requested tender FOR UPDATE, which conflicted
with the other's FK lock. A deterministic two-connection test reproduced
`deadlock detected (SQLSTATE 40P01)`.

Use FOR NO KEY UPDATE for financial revision serialization. MCP row/source
locks use NOWAIT to avoid cycles with portal operations, which lock BOQ rows
before updating the tender. Busy locks return `DIRECT_PRICING_BUSY`; no receipt,
revision or partial BOQ write survives. Tests cover simultaneous commands and
a portal-locked row.

### P1 — numeric-rate-only check misses source changes

Changing a library source from RUB to USD while keeping the rate unchanged
was accepted after service preparation. Delivery, consumption and unit edits
had the same gap. The client also had no way to bind consent to the selected
complete source snapshot.

Search/lookup now returns `source_version`; source-backed writes require
`expected_source_version`. The version covers all copied price/recipe/quote
fields and source context. Service validates it, then the transaction locks
the contributing rows and reads/validates it again. Tests cover source currency
drift before commit; currency/delivery/consumption drift before service;
version sensitivity to units/quote; search-to-commit version parity.

### P2 — previous quote evidence survives a new price

Library repricing retained the old archive quote link and dates. Archive
repricing copied only non-null quote fields, so it could mix a new quote date
with the previous source's expiry and incorrectly reject the write.

Quote link/date/expiry are replaced as one snapshot; missing fields are cleared.
Full replacement validation uses only the proposed dates. Tests verify clearing
archive evidence on library repricing and replacing an archive date without
retaining an older expiry.

### P2 — receipt replay skips missed post-commit work

A process stopping after DB commit but before invalidation/enqueue left stale
cache/commercial calculations. Retrying returned the stored receipt before
repairing those side effects. An integration test reproduced the stale cache.

Successful writes and recovered receipts now run the same idempotent
invalidation/enqueue callback. This does not reapply the BOQ command or bump
its financial input revision. The write-disable flag still blocks new writes.
