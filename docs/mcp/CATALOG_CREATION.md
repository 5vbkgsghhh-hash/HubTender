# Создание работ и материалов через MCP

## Возможности и права

MCP 2.1 содержит 21 инструмент. Добавлены:

| Инструмент | Назначение |
| --- | --- |
| `tenderhub_list_units` | Найти действующую единицу измерения |
| `tenderhub_search_nomenclature` | Найти название работы/материала, даже если цены в библиотеке ещё нет |
| `tenderhub_create_unit` | Создать единицу; существующий активный код вернуть без изменения |
| `tenderhub_create_nomenclature_item` | Создать название работы/материала или вернуть одно точное совпадение |
| `tenderhub_create_library_item` | Создать карточку с указанной ценой, валютой и рецептом материала |
| `tenderhub_get_catalog_creation_receipt` | Восстановить результат по ключу запроса после потерянного ответа |

По прямому решению владельца задачи инженеру разрешено **создание** через MCP.
Допустимые роли: `engineer`, `veduschiy_inzhener`, `administrator`, `developer`,
с доступом к `/library` и активным OAuth grant. Права проверяются по текущей
учётной записи, а не по устаревшему названию роли в токене. Новые инструменты
не предоставляют редактирование/удаление общих записей; права портала и
шаблонов остаются прежними.

Нужны отдельные OAuth-разрешения `nomenclature:create` и `library:create`.
Старый токен не получает их автоматически: следует переподключить клиента и
подтвердить расширенный набор прав. Каждая команда создания отдельно показывает
эффективные значения для подтверждения.

## Последовательность

1. Найти активный код единицы через `tenderhub_list_units`; новую единицу
   создавать только при отсутствии подходящего кода. Регистр кода значим:
   SI-префиксы `M` и `m` отличаются. Единица не активируется/не переименовывается
   скрытно при совпадении с существующей.
2. Найти номенклатуру по `kind=work/material`, названию и единице. Если её нет,
   создать через `tenderhub_create_nomenclature_item`. Ответ содержит ID и
   `nomenclature_item.version`.
3. Для карточки передать `name_id`, `expected_name_version`, положительную
   `unit_rate`, явную `currency` и `price_source`: идентификатор/ссылку КП или
   указание на цену, прямо сообщённую пользователем. Цену не придумывать.
4. У новой работы тип по умолчанию `раб`. У материала — `мат`, `основн.`,
   расход 1, доставка `в цене`, сумма доставки 0. Эти значения показываются
   перед подтверждением. Материал может использовать `суммой` или `не в цене`
   и подтверждённый расход. Объём ВОР при этом не задаётся.
5. Ответ карточки содержит `library_item.id` и `library_item.source_version`.
   Использовать их в существующем `tenderhub_price_boq_item` для добавления в ВОР,
   с категорией затрат, свежей ревизией и отдельным подтверждением.
6. Для материала указать `parent_work_item_id` и при необходимости коэффициент
   перевода. **Не передавать quantity**: сервер считает объём от работы.

Изменение названия/единицы между выбором и созданием карточки приводит к
`CATALOG_NAME_STALE`. Это предотвращает создание цены на ошибочную единицу.

## Дубли, повтор и аудит

- Названия сравниваются по регистру/пробелам и одному точному коду единицы.
  Работа и материал — разные справочники.
- Одно точное совпадение возвращается без изменения. Несколько исторических
  совпадений дают `CATALOG_DUPLICATE_AMBIGUOUS`: выбрать ID из поиска; данные
  не объединяются и не удаляются.
- Карточка сравнивается по номенклатуре, типам, цене, валюте, расходу и доставке.
  Идентичная карточка используется повторно; другие подтверждённые цены/рецепты
  являются отдельными вариантами. При нескольких точных совпадениях выбрать
  существующую карточку через поиск библиотеки.
- Транзакционные advisory locks сериализуют одновременные создания через MCP.
  Это не меняет исторические ограничения и поведение других путей импорта.
- Для новой команды нужен новый `request_key` (16–80 допустимых символов).
  Повтор идентичных аргументов возвращает записанный результат; изменение
  аргументов под тем же ключом даёт `CATALOG_REQUEST_KEY_REUSED`.
- В `mcp_catalog_creation_requests` вместе с созданием коммитятся пользователь,
  клиент, подтверждённые входные данные (включая источник цены), время и результат.
  Ошибка откатывает и запись, и квитанцию. После повтора восстанавливается сброс
  кэшей справочников/библиотеки. Новое создание не изменяет ни один тендер само
  по себе — запись в ВОР выполняется отдельным инструментом.

## Выкладка

После миграций v1 и прямой расценки применить:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f db/yandex/incremental/2026_10_tenderhub_mcp_catalog_creation.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f scripts/mcp/verify_catalog_migration.sql
```

Ожидается `MCP_CATALOG_MIGRATION_OK`. Миграция добавляет квитанции и обычные
индексы; существующие справочники и дубли не исправляет и не удаляет.

После staging-проверки включить на сервере:

```dotenv
MCP_WRITE_ENABLED=true
MCP_CATALOG_WRITE_ENABLED=true
MCP_TEMPLATE_WRITE_ENABLED=false
```

Затем перезапустить BFF и обновить OAuth с двумя create-разрешениями.
При выключенном флаге новые создания запрещены; ранее выполненную команду
можно восстановить без повторного создания. Разрешение `templates:write` этим
не выдаётся.
