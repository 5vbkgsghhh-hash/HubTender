# Полное ревью команд создания каталогов

Дата: 07.10.2026, Europe/Moscow. Проверена версия PR #1 `26b88b9`.
Права инженера на создание подтверждены владельцем задачи. Проверки записи
выполнялись только в отдельной локальной PostgreSQL 17, не в рабочем портале.

## Найдено и исправлено

### P1 — подтверждение показывало округлённую цену

Формат `%.6g` показывал для `12345.67` значение `12345.7`, хотя записывалась
полная цена. Таким образом пользователь подтверждал не те числа, которые
попадали в библиотеку. HTTP MCP-тест воспроизвёл различие.

Цена теперь выводится без потери цифр (`FormatFloat` с точностью -1).
В тесте реальный клиент проверяет точную цену в сообщении подтверждения.

### P2 — повтор блокировался после изменения номенклатуры

При идентичном повторе создания карточки предварительное описание заново
проверяло живую номенклатуру. Её переименование после уже успешного коммита
давало `CATALOG_NAME_STALE` раньше восстановления записанной квитанции.
Service-тест повторов этого не выявлял: дефект находился перед исполнением,
в HTTP/MCP-сценарии подтверждения.

Предварительное описание сначала проверяет существующую квитанцию по
пользователю, клиенту и полному отпечатку нормализованных подтверждённых данных.
Для совпадающего запроса описывается исходный снимок; повтор возвращает прежний
результат без создания/изменения записей. Другие параметры с тем же ключом
отклоняются. Права и активность пользователя/grant по-прежнему проверяются.

## Проверенные области

- Все три команды создания, поиск номенклатуры/единиц, чтение квитанции и
  фактические бизнес-значения в подтверждении.
- OAuth create-scopes, текущая роль/доступ `/library`, отдельный и общий флаги;
  read-only scope и поддельная роль не дают создания.
- Цена, явная валюта, источник цены, типы работы/материала, расход, доставка,
  UUID/версия номенклатуры, пустые/неконечные/несогласованные значения.
- Неактивная единица запрещена; единицы и SI-префиксы не сравниваются без
  учёта регистра.
- Точные совпадения не перезаписываются. Несколько исторических совпадений
  приводят к ошибке выбора; данные не объединяются автоматически.
- Concurrent MCP creation сериализовано; история других путей импорта/портала
  и её дубли сохраняются. Это не объявляется глобальным UNIQUE-ограничением.
- Ошибка откатывает сущность/квитанцию; квитанция принадлежит своему актору.
- Полная цепочка инженер → единица → названия → карточки → ВОР, включая запрет
  ручного объёма связанного материала и пересчёт от работы.
- Повтор по прежней версии после переименования, несовпадающие ключи/аргументы,
  отзыв OAuth grant и типизированные результаты реального MCP SDK.

## Итог

Оба дефекта имели падающий HTTP-тест до исправления. После него HTTP-тест,
новые проверки отрицательных сценариев, прежние catalog/direct/linked/OAuth
интеграционные тесты, Go unit tests, vet и сборка проходят. Конкурентное создание
проверено десять раз. Миграции не менялись относительно предыдущего пакета.
Проверка клиента и данных после staging/production выкладки остаётся обязательной;
это ревью не является подтверждением уже выполненной выкладки.
