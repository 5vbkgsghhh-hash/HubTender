# Ревью проверок MCP — 16.10.2026

База: `origin/main` / `5beefd8`. Изменения относятся к прямой записи MCP и
созданию карточек библиотеки через MCP. UI и обычный импорт не изменяются.

## Исправлено при ревью

1. Подтверждение, связанное только со списком замечаний, пропустило бы изменение
   количества ГП с 10 на 11, если оба значения не вызывают замечаний. Отпечаток
   теперь включает полный предполагаемый снимок позиции и строк. Исключены
   сгенерированный ID новой строки и служебные timestamps, чтобы повторная
   проверка того же предложения давала тот же результат.
2. Комплексный источник мог бы попасть в обновление существующей суб-строки,
   хотя создание новой комплексной строки было запрещено. Источники комплексных
   типов теперь отклоняются в обоих путях.
3. Пересчёт работы может затронуть старого дочернего материала из другой позиции.
   Такой случай теперь откатывает всю операцию как F, даже если устаревшая БД
   содержит историческую связь, предшествующую составным FK.

## Подтверждено тестами

- Набор содержит ровно 17 выбранных активных правил, без E, P, V и GA.
- Предварительный расчёт не сохраняет строки, аудит, квитанции, ГП или ревизию.
- U блокирует отсутствие ГП; явное position_quantity позволяет завершить запись.
- Изменяемая строка без цены, единицы, категории или с комплексным типом отклоняется.
- A, AB, I и L в существующих строках целевой позиции блокируют новую запись.
  После отказа количество строк, квитанций и финансовая ревизия не меняются.
- Работа пересчитывает материал и итоги позиции; результат проходит A/AB/I/J.
- Ручное quantity связанного материала отвергается.
- R требует подтверждения; изменение набора замечаний отменяет старое согласие.
- Изменение ГП без новых замечаний тоже отменяет старое согласие.
- Настоящий HTTP MCP-клиент без elicitation получает S в тексте подтверждения;
  до согласия ревизия не меняется, после — запись проходит.
- Повтор request_key возвращает квитанцию без дублирования записи.
- Карточки MCP допускают только суб-раб/суб-мат, расход >= 1 и положительную
  стоимость доставки для типа «суммой».
- Прежние сценарии источников/source_version, конкурентной записи, OAuth,
  создания библиотеки и восстановления квитанций проходят.

## Команды

На отдельном PostgreSQL 17, localhost:55446, подготовлены baseline, миграции
и evaluation_fixture. Данные продакшена не загружались.

```powershell
go test -p 1 -buildvcs=false -tags=integration ./internal/services ./internal/mcpserver ./internal/mcpauth -run 'Catalog|DirectPricing|AuthenticatedHTTP|OAuth|MCPPricing' -count=1
go test -buildvcs=false ./internal/pricing ./internal/repository ./internal/services ./internal/mcpserver
go vet ./internal/pricing ./internal/repository ./internal/services ./internal/mcpserver
go build -buildvcs=false -o NUL ./cmd/server
```

Все перечисленные команды завершились успешно. Параметр buildvcs=false обходит
известную особенность локального Windows linked worktree.

## Оставшиеся границы

- Это не защита владельца расчёта. Авторизация чужих правок и обычных API
  удаления/очистки требует отдельной реализации.
- Не проверялись production-выкладка и задержки проверок на большом рабочем тендере.
- Старые ошибки в целевой позиции блокируют её последующие записи MCP; обычная
  страница портала остаётся доступна для исправления исходных данных.
- Общий базовый QA MCP не стал полным отчётом страницы «Проверка данных».
