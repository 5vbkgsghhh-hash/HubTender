# Владение расчётом позиции

## Перед выкладкой

1. На staging с копией схемы/данных сделать резервную копию и остановить записи
   расценки портала/MCP на время согласованной миграции и обновления BFF.
2. Применить `db/yandex/incremental/2026_10_mcp_pricing_ownership.sql` после
   существующих миграций. Она сохраняет данные, устанавливает владельцев и
   триггеры. Повторный запуск не перезаписывает уже назначенного владельца.
3. Сверить `origin` и число `owner_id IS NULL` в `position_pricing_owners`.
   Смешанные/неизвестные авторы требуют разбора первого INSERT-аудита и импорта.
   Не назначать текущего инженера, последнего редактора или создателя тендера
   автоматически. Удалённые пользователи не превращают расчёт в свободный.
4. При отдельной runtime-роли БД дать ей обычные права SELECT/INSERT/UPDATE
   на новые таблицы (DELETE нужен только оператору), EXECUTE на функции и права
   чтения связанного аудита. Проверить реальным runtime-подключением.
   Функции работают с правами вызывающего, без SECURITY DEFINER.
5. Выкатить BFF с передачей проверенного JWT/API-key автора в транзакции.
   Старый BFF без этой передачи несовместим с договорённостью о владельце.
6. Выполнить `scripts/mcp/verify_pricing_ownership.sql` и сценарии ниже.
   После приёмки открыть запись. В этой ветке нет развёртывания на production.

## Приёмка двумя инженерами

- A создаёт расчёт пустой позиции; БД фиксирует A. Preview не фиксирует владельца.
- B читает расчёт и копирует его в свою пустую позицию.
- B получает отказ при добавлении/правке/удалении строки в позиции A, смене ГП,
  импорте в эту позицию, очистке ВОР, отмене импорта A, восстановлении из аудита,
  удалении позиции/тендера. Роль администратора не меняет этот результат.
- После отказа строки, ГП, ревизия, аудит и квитанции неизменны.
- A может править и очищать свой расчёт; после очистки B всё ещё не может его
  присвоить. Восстановление сохраняет прежнего владельца.
- Неатрибутированная/смешанная старая позиция закрыта обоим до решения оператора.
- Смена названия номенклатуры между показом и подтверждением отменяет согласие.
- Изменение ГП сохраняет old/new и автора; preview и отказ не сохраняют аудит.

Граница владельца — вся расценка одной позиции. Совместное редактирование
чужой позиции этой версией не разрешается. Передача владения через MCP отсутствует;
операторское назначение выполняется отдельно по проверенным основаниям.
