# Запуск портала на локальной машине

Пошаговая инструкция: от чистой системы до работающего портала в браузере.

---

## 1. Предустановленные программы

| Что | Зачем | Проверить |
|---|---|---|
| [Node.js 18+](https://nodejs.org/) | фронт (Vite + React) | `node -v` |
| [Go 1.23+](https://go.dev/dl/) **или** [Docker Desktop](https://www.docker.com/products/docker-desktop/) | бэк (Go BFF) | `go version` / `docker --version` |
| [git](https://git-scm.com/) | клонирование репозитория | `git --version` |

**Достаточно одного из двух**: если Go установлен — бэкенд запускается нативно, иначе `npm run dev:backend` автоматически соберёт его в Docker.

---

## 2. Склонировать репозиторий

```bash
git clone https://github.com/baldmaxim/HubTender.git
cd HubTender
```

---

## 3. Настроить переменные окружения

Скопировать шаблон и заполнить реальными значениями:

```bash
cp .env.example .env
```

Открыть `.env` и подставить (значения — у администратора проекта):

| Переменная | Что это |
|---|---|
| `DATABASE_URL` | строка подключения к Yandex Managed PostgreSQL (`sslmode=verify-full`) |
| `APP_JWT_ISSUER`, `APP_JWT_AUDIENCE` | параметры app-auth JWT |
| `APP_JWT_PRIVATE_KEY_PATH` **или** `APP_JWT_PRIVATE_KEY_B64` | приватный RS256-ключ для подписи токенов |

Остальные переменные (`VITE_API_URL`, `VITE_API_REALTIME_ENABLED`) уже настроены с правильными дефолтами — см. [.env.example](.env.example) и [docs/RUNTIME_ENV.md](docs/RUNTIME_ENV.md).

> ⚠️ `.env` в `.gitignore` — в репозиторий он не попадёт. Секреты никогда не префиксовать `VITE_`.

---

## 4. Установить зависимости фронта

```bash
npm install
```

---

## 5. Запустить бэкенд (Go BFF)

В **первом терминале** из корня репозитория:

```bash
npm run dev:backend
```

Скрипт сам подтянет `.env`, скачает CA-сертификат Yandex (при первом запуске) и поднимет Go BFF на `http://localhost:3005` — нативно через `go run`, а если Go не установлен — соберёт и запустит Docker-образ.

Проверить, что бэкенд поднялся:

```bash
curl http://localhost:3005/health      # должен вернуть OK
curl http://localhost:3005/health/db   # должен подтвердить коннект к БД
```

Если один из healthcheck'ов падает — смотреть логи в терминале с `dev:backend`.

---

## 6. Запустить фронтенд (Vite dev-server)

Во **втором терминале** (первый оставить с бэкендом):

```bash
npm run dev
```

Vite автоматически откроет **http://localhost:5185** в браузере. Hot Module Replacement (HMR) включён — правки в `src/` применяются мгновенно.

---

## 7. Зайти в портал

На странице логина ввести email/пароль учётки портала (auth — собственный, RS256 JWT выдаёт Go BFF). Если пользователей нет — зарегистрироваться через форму `/register` (доступ активирует администратор).

После успешного входа — редирект на `/dashboard`.

---

## Остановка

- Фронт: `Ctrl+C` в терминале с `npm run dev`
- Бэк: `Ctrl+C` в терминале с `npm run dev:backend`

---

## Troubleshooting

**Порт 5185 уже занят** — поменять в [vite.config.ts](vite.config.ts) на любой свободный (и обновить `DEV_CORS_ORIGINS` в `.env`, если задан).

**Порт 3005 уже занят** — задать `DEV_BACKEND_PORT` в `.env` (его читает `scripts/dev-backend.ps1`) и поменять `VITE_API_URL`.

**Бэкенд падает с ошибкой про DATABASE_URL / TLS** — проверить, что в `DATABASE_URL` указан `sslmode=verify-full`; CA-сертификат Yandex скрипт скачивает сам в `certs/yandex-ca.pem`.

**Фронт поднимается, но логин не работает (401/403)** — проверить `APP_JWT_*`-переменные в `.env`: бэкенд не подпишет токены без приватного ключа (`APP_JWT_PRIVATE_KEY_PATH` или `APP_JWT_PRIVATE_KEY_B64`).
